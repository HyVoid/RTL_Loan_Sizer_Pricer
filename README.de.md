## 4 versteckte blinde Flecken, die Private-Lending-Deals killen

Selbst erfahrene Loan Originators und aktive Flips machen teure Fehler, wenn sie Kennzahlen einzeln in verstreuten Rechnern prüfen:

1. **Die Ein-Kennzahlen-Falle (LTV sieht gut aus, LTARV killt den Deal):** Ein Fix-and-Flip-Deal kann bequem bei **76.2% As-Is-LTV** liegen und trotzdem eine **88% LTARV**-Richtlinienobergrenze verletzen, sobald ein hohes Sanierungsbudget hinzukommt. Wer alle vier Leverage-Obergrenzen gemeinsam prüft, findet Deal-Killer in Sekunden.
2. **Die Zins-vs.-Spread-Falle (Volumen gewonnen, Gewinn verloren):** Senkt man den Note Rate eines Kreditnehmers auf **10.00%** gegen einen **8.20%** Buy Rate, bleiben nur **1.80% Spread** – was still eine **2.50% Mindest-Spread-Untergrenze** verletzt. Die automatisierte Validierung findet die Margenerosion, *bevor* das Term Sheet Ihren Schreibtisch verlässt.
3. **Die Cash-to-Close-Falle (Anzahlung != gesamte Bargeldsumme):** Bei einem **$450,000**-Darlehen senken **$6,250** vorausbezahlte Short Interest und **$2,250** Servicing-Gebühren den Net Funding auf **$441,500** – aus einer erwarteten Lücke werden **$26,500** tatsächlicher Cash-to-Close. Hält der Kreditnehmer nur **$18,000** flüssig, erkennen Sie die **$8,500**-Lücke sofort statt erst drei Tage vor dem Settlement.
4. **Die Preis-Leakage-Falle:** Das Teilen einer ungeschützten Preistabelle exponiert Ihre Wholesale-Kapitalkosten und Gewinnregeln. Getrennte Eingaben, Preisraster und Kunden-Outputs halten Ihre Kalkulation privat, während Ihre Vertreter schnell quoten können.

## Häufig gestellte Fragen

<details>
<summary><strong>Was ist der Unterschied zwischen LTV, LTC, LTP und LTARV?</strong></summary>

- **LTV (Loan-to-Value):** Darlehensbetrag geteilt durch den aktuellen As-Is-Beleihungswert der Immobilie.
- **LTP (Loan-to-Purchase):** Erwerbsauszahlung geteilt durch den vertraglichen Kaufpreis.
- **LTC (Loan-to-Cost):** Gesamtdarlehensbetrag geteilt durch die Gesamtprojektkosten (Kaufpreis + Sanierungsbudget).
- **LTARV (Loan-to-After-Repair-Value):** Gesamtdarlehensbetrag geteilt durch den projizierten After Repair Value (ARV) nach Abschluss der Sanierung.

Da RTL-Lender alle vier Kennzahlen gleichzeitig begrenzen, bindet der strengste Wert die maximal förderfähige Darlehensgröße.
</details>

<details>
<summary><strong>Brauche ich fortgeschrittene Excel-Kenntnisse oder Makros für die Offline-Vorlage?</strong></summary>

Nein. Jedes Lookup-Raster, jede Leverage-Obergrenze und jede Settlement-Formel ist zu 100 % vorgebaut mit nativen Excel-Formeln (für die täglichen Berechnungen sind null VBA/Makros nötig). Fügen Sie einfach die Deal-Zahlen in `02_Inputs` ein und lesen Sie die Ergebnisse auf `05_Quote_Summary` ab. **Microsoft 365** oder **Excel 2021+** wird für volle native `XLOOKUP`-Kompatibilität empfohlen.
</details>

<details>
<summary><strong>Kann ich meine Wholesale-Buy Rates verstecken, bevor ich die Vorlage an Loan Officers weitergebe?</strong></summary>

Ja. Preisregeln und Buy-Rate-Tabellen sind auf `03_Pricing_&_Assumptions` isoliert und die Berechnungen auf `04_Calc_Engine` – ausgelegt, um eine geschützte **Originator-Version** (Preis-Tabs sperren/verstecken) neben Ihrer vollständigen **Internal-Admin-Version** zu unterstützen.
</details>

### Durchgerechnetes Beispielszenario (Fix-and-Flip-Darlehensbemessung)

| Deal-Eingabe | Wert |
| :--- | ---: |
| Kaufpreis | $300,000 |
| Sanierungsbudget | $70,000 |
| As-Is-Immobilienwert | $310,000 |
| After Repair Value (ARV) | $465,000 |
| Beantragter Darlehensbetrag | $340,000 |
| FICO / Erfahrung des Kreditnehmers | 726 / 6+ Projekte |
| Beantragter Note Rate / Laufzeit | 11.25% / 12 Monate |

**Automatisierte Engine-Ausgaben:**

| Kreditprüfungs-Kennzahl | Berechnetes Ergebnis |
| :--- | ---: |
| Tatsächliches LTV (`340k / 310k`) | **109.7%** *(übersteigt die bevorzugte LTV-Schwelle)* |
| Tatsächliches LTC (`340k / 370k`) | **91.9%** |
| Tatsächliches LTARV (`340k / 465k`) | **73.1%** |
| Lender-Yield-Spread | **3.10%** *(gültig – über der Mindest-Spread-Untergrenze)* |
| **Gesamturteil zur Förderfähigkeit** | **`EXCEPTION NEEDED`** |

Statt ein überleveragedes Darlehen stillschweigend zu genehmigen oder einen profitablen wiederkehrenden Flipper blind abzulehnen, klassifiziert die Engine die Akte als **`EXCEPTION NEEDED`**, damit das Kreditmanagement kompensierende Faktoren (Erfahrung, Liquidität oder Sicherheiten) sofort prüfen kann.

### Referenz der Kernformeln

<details>
<summary>Beleihungs- & Preisformeln</summary>

```excel
Actual_LTV   = IFERROR(LoanAmount / AsIsValue, 0)
Actual_LTC   = IFERROR(LoanAmount / (PurchasePrice + RehabBudget), 0)
Actual_LTP   = IFERROR(LoanAmount / PurchasePrice, 0)
Actual_LTARV = IF(ARV = 0, 0, IFERROR(LoanAmount / ARV, 0))

Spread       = NoteRate - BuyRate
SpreadStatus = IF(Spread < MinimumSpread, "Below Margin", "Valid")
```

*Preistabellen verwenden exaktes `XLOOKUP`-Matching (mit `TRIM` + `UPPER`-Texthygiene und Fallback-Alarmen in Form von `"Check Risk Rules"`).*

</details>

<details>
<summary>Settlement- & Liquiditätsformeln</summary>

```excel
NetFunding         = LoanAmount - ShortInterest - ServiceFee
CashToClose        = MAX(0, TotalProjectCost - NetFunding)
LiquidityShortfall = MAX(0, CashToClose - LiquidAssets)
```

</details>
